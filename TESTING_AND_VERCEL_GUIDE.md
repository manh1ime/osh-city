# Полное тестирование Водопад

## 1. Что проверяем

В системе две роли сотрудников:

- **Официант** работает с заказами и вызовами гостей.
- **Менеджер** видит сводку и все заказы, управляет меню, категориями, стоп-листом, столами, QR-кодами, сотрудниками и настройками ресторана.

У гостя нет учетной записи. Доступ к меню привязан к уникальному QR-токену стола.

## 2. Чистая локальная установка

В PowerShell откройте корень проекта и выполните:

```powershell
npm install
docker compose up -d
npx prisma generate
npx prisma migrate dev
npm run db:seed
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm run dev
```

Ожидаемый результат: приложение доступно на `http://localhost:3000`, терминал не показывает циклические редиректы и runtime errors.

## 3. Проверка учетных записей

### Официант

1. Откройте `http://localhost:3000/staff/login`.
2. Войдите: `waiter@demo.ru`, пароль `demo123`.
3. Убедитесь, что доступны «Заказы» и «Вызовы».
4. Попробуйте открыть `/manager`.
5. Ожидаемый результат: официант перенаправлен в `/staff/orders`.

### Менеджер

1. Выйдите из аккаунта официанта.
2. Откройте `http://localhost:3000/manager/login`.
3. Войдите: `manager@demo.ru`, пароль `demo123`.
4. Проверьте разделы: сводка, заказы, меню, категории, столы и QR, сотрудники, настройки.
5. Откройте каждый раздел и убедитесь, что нет ошибок.

### Удаленная роль

1. Убедитесь, что `/admin` и `/admin/login` не существуют.
2. Убедитесь, что учетная запись `admin@demo.ru` больше не создается.
3. В разделе сотрудников должны быть доступны только роли «Официант» и «Менеджер».

## 4. Проверка меню менеджером

1. Откройте `/manager/menu`.
2. Измените цену тестового блюда.
3. Измените описание.
4. Поместите блюдо в стоп-лист.
5. Откройте гостевое меню и проверьте обновления.
6. Верните исходную цену и снимите стоп-лист.

Проверьте категории:

1. Создайте тестовую категорию.
2. Измените ее название.
3. Отключите категорию.
4. Убедитесь, что она скрылась у гостя.
5. Удалите тестовую категорию, если она больше не нужна.

## 5. Проверка столов и QR-кода

1. Войдите менеджером.
2. Откройте `/manager/tables`.
3. Выберите активный стол.
4. Скачайте QR-код.
5. Не используйте скриншот ссылки вместо самого QR-кода.
6. Откройте QR камерой телефона.

Для локальной проверки телефон и компьютер должны находиться в одной Wi-Fi сети. Запустите Next.js с доступом по сети:

```powershell
npm run dev -- --hostname 0.0.0.0
```

Узнайте локальный IPv4 компьютера:

```powershell
ipconfig
```

В `.env` временно задайте адрес компьютера, например:

```env
NEXT_PUBLIC_APP_URL="http://192.168.1.25:3000"
```

Перезапустите сервер и заново скачайте QR-код. Адрес `localhost` на телефоне указывает на сам телефон и для такой проверки не подходит.

Ожидаемый результат:

- QR открывает меню нужного стола;
- показывается правильный номер и зона;
- не требуется регистрация;
- не возникает горизонтальная прокрутка;
- фотографии загружаются;
- недействительный токен показывает аккуратную ошибку.

## 6. Полный сценарий заказа

Используйте телефон как гостя, отдельное окно или устройство как официанта и ноутбук как менеджера.

1. Гость открывает QR-код стола.
2. Находит блюдо через поиск.
3. Открывает карточку блюда.
4. Проверяет состав, вес и аллергены.
5. Добавляет несколько блюд в корзину.
6. Проверяет анимацию попадания в корзину.
7. Меняет количество.
8. Добавляет комментарий к блюду.
9. Добавляет общий комментарий.
10. Отправляет заказ.
11. Официант видит новый заказ без ручного обновления или после штатного обновления панели.
12. Официант открывает подробности и проверяет стол, блюда, комментарии и сумму.
13. Официант принимает заказ.
14. Передает его на кухню.
15. Завершает заказ.
16. Менеджер открывает `/manager/orders` и видит заказ и историю статусов.
17. Гость открывает страницу статуса и видит актуальное состояние.

Дополнительно проверьте отмену на отдельном тестовом заказе.

## 7. Проверка вызова официанта

1. В гостевом меню нажмите «Позвать официанта».
2. Откройте `/staff/calls`.
3. Проверьте номер стола и время вызова.
4. Возьмите вызов в работу.
5. Закройте вызов.
6. Несколько раз быстро нажмите кнопку гостя и убедитесь, что антиспам не создает бесконечные дубли.

## 8. Проверка панели менеджера

### Сводка

- отображаются основные показатели;
- последние заказы открываются;
- суммы совпадают с заказами.

### Все заказы

- работают фильтры;
- открываются подробности;
- отображается история статусов;
- суммы и комментарии совпадают.

### Сотрудники

- менеджер может создать официанта;
- новый официант может войти;
- менеджер может отключить сотрудника;
- нельзя отключить собственную учетную запись;
- нельзя отключить последнего активного менеджера;
- роли ограничены официантом и менеджером.

### Настройки

- меняются название, описание и адрес;
- меняется обложка;
- можно временно отключить прием заказов;
- при отключении гость видит понятное сообщение и не может отправить заказ.

## 9. Негативные проверки

Обязательно проверьте:

- неправильный пароль;
- попытку официанта открыть панель менеджера;
- пустую корзину;
- блюдо в стоп-листе;
- неактивный стол;
- поврежденный QR-токен;
- повторную отправку заказа;
- слишком длинный комментарий;
- потерю интернета во время отправки;
- обновление страницы с наполненной корзиной;
- выход из аккаунта и повторный вход.

## 10. Проверка перед Vercel

Перед публикацией выполните:

```powershell
npx prisma generate
npm run typecheck
npm run build
```

Если команда падает, публикацию откладываем до исправления ошибки. Не переносите локальный PostgreSQL из Docker на Vercel. Для Vercel нужна облачная PostgreSQL, например Neon, Supabase или Vercel Postgres.

В Vercel потребуется задать:

```env
DATABASE_URL="строка подключения облачной PostgreSQL"
AUTH_SECRET="длинный случайный секрет минимум 32 символа"
HASH_SALT="отдельный случайный секрет"
NEXT_PUBLIC_APP_URL="https://ваш-домен.vercel.app"
SEED_DEMO_PASSWORD="надежный демо-пароль"
```

После первого подключения облачной базы:

```bash
npx prisma migrate deploy
npm run db:seed
```

Не публикуйте реальные секреты в GitHub.

## 11. Проверка на Vercel

1. Откройте главную страницу в режиме инкогнито.
2. Проверьте вход официанта.
3. Проверьте вход менеджера.
4. Скачайте новый QR-код после установки `NEXT_PUBLIC_APP_URL`.
5. Откройте QR через мобильный интернет, не через локальную сеть.
6. Создайте полный заказ.
7. Пройдите все статусы.
8. Проверьте вызов официанта.
9. Проверьте изменение стоп-листа.
10. Проверьте изображения и отсутствие смешанного HTTP/HTTPS-контента.
11. Проверьте Chrome, Firefox и Safari или iPhone.
12. Проверьте ширину 390 px и обычный ноутбук.

## 12. Подготовка демо-видео

Перед записью:

- удалите старые тестовые заказы;
- проверьте фотографии и цены;
- откройте нужные вкладки заранее;
- отключите уведомления;
- используйте отдельные окна или профили браузера для официанта и менеджера;
- подготовьте QR-код;
- Запишите резервный дубль без звука.

Рекомендуемый сценарий:

1. Гость сканирует QR и открывает меню.
2. Добавляет три блюда и комментарий.
3. Отправляет заказ.
4. Официант получает и принимает заказ.
5. Менеджер открывает все заказы и сводку.
6. Менеджер показывает меню, стоп-лист и QR-коды.
7. В конце показывается короткое предложение для ресторана.

Оптимальная длина ролика: 3–5 минут. Не показывайте код, терминал, тестовые ошибки и внутренние настройки.
